# Consignes pour les agents - repo Anacoluthe

## Deck de soutenance (`soutenance.html`, `assets/css/soutenance.css`)

- **Format de projection unique : 1920 × 1080.** Vérifier le rendu à cette taille seulement. Ne pas tester ni ajuster d'autres tailles ou proportions (4:3, 1280 × 720, mobile), sauf demande explicite de Quentin.
- **Lisibilité** (retour de l'oral blanc n°1) : pas de texte sous `--t-petit`, contraste texte-fond d'au moins 7:1 pour les petits textes. Pour du texte coloré, utiliser `--teal-texte` et `--amber-texte`, pas `--teal-700` ni `--amber-700`.
- **Pas de texte d'explication ou de précaution à l'écran** (« portraits composites », « intentions formulées après coup », « ce qui les distingue… ») : il se dit à l'oral (cartons de la vue présentateur). L'écran porte le contenu, pas son mode d'emploi. Les sources courtes (extrait des statuts, date d'un vote) restent.
- **Ancres des écrans : `eNN-nom`** (`#e01-intuitions`, `#e21-ecart`). Le numéro est celui de l'écran dans le deck. Le préfixe `e` garde des sélecteurs CSS valides (un identifiant CSS ne commence pas par un chiffre). Tout ajout, retrait ou déplacement d'écran renumérote les ancres suivantes, dans `soutenance.html` et dans `soutenance.css`.
- **Notes de présentation** : `Dossier_UC12_anacoluthe/soutenance/notes-presentation.md` n'est plus tenu à jour (S140). L'aide-mémoire de l'oral, ce sont les cartons (`assets/data/soutenance-cartons.md`), rédigés par Quentin : ne pas en modifier le contenu sans demande.
- Les archives `archives/soutenance/soutenance-oral-blanc-1.html`, `soutenance-oral-blanc-2.html` et `soutenance-oral-blanc-3.html` sont figées, chacune avec sa propre copie du CSS. Ne pas les modifier.
- **Vocabulaire** : les responsables croisière et RTQ s'appellent « les référents de l'activité » (S138), pas « encadrants ».
- Les décisions sur le deck et l'oral se consignent dans le repo du dossier : `Dossier_UC12_anacoluthe/soutenance/DECISIONS_SOUTENANCE.md`. Une entrée par session de travail, pas par retouche : les petites modifications de vibecode (libellé, ordre, taille, mise en gras) se regroupent dans une seule entrée, une puce par écran. Une entrée à part seulement pour un arbitrage de fond (structure, message, retrait d'un écran). Le plan de refonte en cours est dans `Dossier_UC12_anacoluthe/soutenance/CHECKLIST_ORAL_BLANC_2.md` (celui de l'oral blanc n°1 dans `CHECKLIST_ORAL_BLANC_1.md`).
- **Vue présentateur** : la touche S du deck ouvre `soutenance-notes.html` (cartons de l'écran courant et suivant, chrono). Les cartons sont dans `assets/data/soutenance-cartons.md`, lus en ligne : le carton N va avec l'écran eNN. Tout ajout, retrait ou déplacement d'écran renumérote aussi les cartons. La touche N (et S quand le deck tourne dans un cadre, comme l'artefact claude.ai, où la fenêtre liée est bloquée) ouvre la vue intégrée : les mêmes cartons dans un panneau à droite du deck (`soutenance-notes.html?integre=1`).
- **Pas de bordure gauche colorée** (`border-left`) pour signaler un bloc, une carte ou un acte : la couleur passe par le fond, une pastille ou un filet.
